How it works, no jargon

Three pieces, three demo steps

Step 1 · Skills over MCP

The manual comes with the tool

Public beta

Besides the buttons the AI can press, the connector delivers the manual on how to use them, written by the tool's own company. The AI opens the manual only when needed, so it takes almost no space in the conversation.

In the kit, the shop manual says: minimum margin of 15% over cost, never below cost and prices ending in ,90. The demo checks that the manual arrived complete.

In everyday terms: it's the appliance that comes with the manual in the box, and the maker updates the manual automatically when it improves.
Step 2 · Tasks

Long work goes to the background

Available

Instead of blocking the conversation, the tool replies right away “got it, I'm working on it” and carries on by itself. The AI checks from time to time and tells you when it's done.

In the kit, a 20% discount on 300 products becomes a task: progress shows up 50 at a time until “done”, with 299 new prices in the draft and 43 held at the margin.

In everyday terms: it's dropping off your clothes at the laundry and getting a ticket. You leave and come back to ask if they're ready.
Step 3 · Elicitation

The tool asks before acting

Available

In the middle of the job, the tool stops and asks you. It can be a question right in the chat (yes or no, type the name) or a link to the company's website, for passwords or payment: that way sensitive data doesn't go through the chat.

In the kit: “Publicar 299 preços novos agora?” (Publish 299 new prices now?). With “no”, nothing is published; with “yes”, the prices go to the shop. To delete, typing just “Caneca” (mug) isn't enough: it has to be “Caneca Azul P” (small blue mug).

In everyday terms: it's the bank asking you to confirm the amount before a transfer.

What the kit doesn't promise

  • The shop is pretend: 300 made-up products, and the server works on a copy. It doesn't connect to your real shop.
  • Tasks live only in the server's memory: if it restarts, they're gone.
  • In Claude Code, the kit proved the connection and the manual showing up; the task and the question were proven by the demo and the tests (see The proof).

For server builders

The three pieces by their official names

This is the only technical part of the guide. Each term comes with a plain sentence next to it; the rest is in the README.

📘 Manual included: skills/list and skills/get

“The server says which manuals it has and delivers the one you ask for.” It's the io.modelcontextprotocol/skills extension; the manual files come out through resources/read. In the kit, the promocao manual comes with a list of files with size and SHA-256 (a digital fingerprint of the file), and the client checks them. In Claude Code the name appears as <servidor>:<skill>.

⏳ Background: taskId and tasks/get

“The server hands back a ticket right away and the client asks how it's going.” The states are working, completed, failed, cancelled and input_required. A client that doesn't declare the extension gets the result the old way (waits and returns).

❓ Asks first: elicitation form × url

“Form” is the question in the chat: yes or no, type the name. “Url” sends the person to the company's website (password, payment), and the data doesn't go through the chat. The kit uses form; url is only mentioned, because the small shop doesn't ask for sensitive data.

🏪 The kit's server

servidor.py is a “loja” (shop) MCP server that talks through the terminal's input and output (stdio): the promocao manual, the atualizar_precos tool (becomes a task), publicar_precos (asks yes or no) and apagar_produto (asks for the exact name). The mcp 2.3.0 Python SDK doesn't ship the skills and tasks extensions ready-made: the kit writes them by hand.

Run it in 3 commands (Python 3.10+)

git clone https://github.com/inematds/mcp2-na-pratica
cd mcp2-na-pratica
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python demo.py --auto

Without --auto, the demo asks you the questions. Tests: .venv/bin/python -m pytest -q.

Connect it to Claude Code

claude mcp add loja -- "$PWD/.venv/bin/python" "$PWD/servidor.py"
claude mcp list   # loja: … - ✔ Connected

Inside claude: /mcp → loja and /skills → loja:promocao. With --scope project it stays “Pending approval” until you open claude in the folder; the default scope (local) connects right away. To remove it: claude mcp remove loja.

Honest limits: tasks live only in the server's memory, ttlMs is reported but deletes nothing on its own, and tasks/update only confirms receipt. The kit speaks the 2026-07-28 version of the specification, the “stateless” one: simple request and response, which even lets the server run on serverless. Details in the README and COMO-LIGAR-NO-CLAUDE.md (in Portuguese).

Questions

Before you ask

Do I need to code?

Not to see it working: you paste the request from “How to start” and your AI does the rest. To build your own server, yes, and the Python kit is the starting point.

Does it cost anything?

The kit is free and open (MIT license). The updates in Claude are turned on in the Pro, Max and Ultra plans, which are paid.

Is “MCP 2.0” the official name?

No. It's the nickname going around for the November 24, 2026 package. The standard is still MCP, which turned 2 in November 2026.

Does it work with other AIs?

MCP is open and was adopted by OpenAI, Google and Microsoft. Each AI app has to support the new pieces; the kit was tested in Claude Code. The demo runs on its own in the terminal, with any agent.

Does it touch my real shop?

No. The shop is made up and the server works on a copy of the 300 products.

Can I send a file to the tool?

Not yet. File sending (File Uploads) was announced as “coming soon”, with no date.
